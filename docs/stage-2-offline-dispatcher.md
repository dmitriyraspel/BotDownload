# Этап 1 — очередь и диспетчер (offline)

## Порядок работ
1. Очередь и диспетчер.
2. Отмена задач.
3. Аварии и восстановление.
4. Финальная интеграция.

## Границы безопасности
`bot.offline_dispatcher.run_offline_dispatcher` — явный тестовый контур,
не подключённый к Telegram polling. Он последовательно выбирает задачи
из указанной SQLite, выдаёт ограниченный lease, передаёт его по Unix IPC
изолированному offline worker и сохраняет фиксированный offline-артефакт.
Этот артефакт не является медиа и не должен отправляться пользователям.

Обычная Telegram-очередь в режиме отключённых скачиваний только хранит
выбор пользователя и обслуживает истечение срока ожидания; она не запускает
offline-диспетчер и не подменяет скачивание тестовым результатом.

## Проверка
`python -m pytest -q tests/test_offline_dispatcher.py tests/test_cancel_worker_lifecycle.py`

Интеграционный маршрут для отдельной тестовой БД:
`run_offline_dispatcher(stop=..., db_path=..., socket_path=..., configured_download_dir=...)`.
Остановить через `stop.set()`. Параллельное выполнение задач запрещено
последовательным циклом; остановка не прерывает уже выполняемую задачу
(её отмена — этап 2).

Нельзя запускать этот контур с рабочей БД пользовательских задач.
