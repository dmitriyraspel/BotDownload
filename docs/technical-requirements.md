# BotDownload — техническое задание и статус реализации

Дата фиксации: 2026-11-03. Для безопасности в v1 приоритет имеет
[SECURITY_POLICY_V1.md](SECURITY_POLICY_V1.md) (утверждена 2026-11-03).
Этот документ отражает технический план и исторический статус; при
противоречиях применять утверждённую политику v1.

## Назначение и платформа

Telegram-бот на Python / aiogram для получения видео и MP3 из YouTube, Instagram, TikTok. Debian 12 (фактический сервер), возможна разработка/проверка на Windows. yt-dlp, FFmpeg/ffprobe, SQLite, `config.yaml`, секреты в `.env`. Ветка разработки `feature/stage-2-telegram`; **не сливать PR и не менять main без разрешения владельца**.

## Интерфейс Telegram

- Одно сообщение пользователя содержит ровно одну HTTPS-ссылку; только поддерживаемые сайты и проверенные домены, без похожих доменных имён.
- Сначала сообщение «анализирую», затем одна карточка с обложкой (если доступна), названием, продолжительностью, языком, вариантами форматов и приблизительным размером.
- Кнопки 480p, 720p, 1080p и MP3, если соответствующий вариант доступен.
- После выбора редактировать ту же карточку (статус, без кнопок); готовый файл отправлять отдельным сообщением.
- Предпочитать русскую аудиодорожку при наличии, иначе оригинальную.
- MP4: H.264/AAC; MP3: VBR `-q:a 0`.

## Очередь, лимиты и доставка

- Один рабочий обработчик очереди; не более 20 ожидающих задач; ожидание не дольше 30 минут.
- Ограниченные повторы скачивания/отправки, тайм-ауты, проверка свободного места и максимального размера файла.
- Не более 3 успешных **новых** доставок на пользователя за сутки UTC; доверенные пользователи без лимита. Повторная отправка из кэша не расходует лимит.
- Кэш Telegram `file_id`, учёт задач и идемпотентность в SQLite.
- Защита от спама, временные блокировки, резервные копии, административные возможности.
- Режим Telegram API выбирается явно: cloud (до 50 MB) или local (до 2000 MB); без автоматического переключения.

## Безопасность

- Проверка URL и направлений фактических сетевых соединений yt-dlp/дочерних процессов. Сетевая блокировка v1 касается **только** `127.0.0.0/8` и `::1/128`; остальные частные, link-local, metadata и Fake-IP диапазоны не блокируются до v2. Проверять соблюдение этого запрета при внутренних запросах и редиректах, сохраняя системный DNS. Остаточный SSRF-риск для остальных внутренних адресов признан в политике v1.
- Проверять внутренние запросы экстракторов, включая плейлисты, сегменты, картинки и редиректы.
- FFmpeg работает только с локальными файлами допустимых типов; фиксированные аргументы, ограничение времени и размера результата, безопасная остановка процессов.
- Для недоверенного медиа нужны изоляция сети, лимиты CPU/RAM и проверка ресурсов.
- Секреты не логировать и не коммитить; пользователь службы не должен иметь права изменять код.

## Хранение

- `storage.download_dir` задаёт внешний каталог, фактическое значение на сервере: `/var/www/botdownload_files`. Возможен отдельный диск/монтирование.
- Для каждой задачи отдельный приватный каталог; удаление только собственных временных файлов. Не трогать чужие файлы в корне.
- Требуется определить политику постоянного хранения после успешной отправки: **решение владельца пока не получено**. До решения не удалять произвольные пользовательские файлы.
- SQLite `data/bot.sqlite`, логи `logs/bot.log`; рабочие каталоги доступны `tgbot` на запись.
- Фактический пользователь Debian: `tgbot`, без домашнего каталога и без возможности входа. Код под `root`, секреты `root:tgbot` 640.

## Текущий статус (2026-11-03)

- Telegram polling, анализ метаданных, карточки вариантов, кнопки и предварительная очередь реализованы частично.
- SQLite-схема очереди, кэша, лимитов, блокировок; тесты URL/FFmpeg; `bot/download_storage.py` для отдельных временных каталогов.
- Подтверждено пользователем: **52 passed in 3.28s** на Debian 12.
- **Реальные загрузки в Telegram намеренно отключены.** Сетевой транспорт yt-dlp не изолирован, очередь не исполняет скачивания, модуль каталогов не подключён к загрузчику.
- Остаётся: безопасный транспорт и DNS rebinding/redirect защита, ограничение ресурсов, подключение очереди и скачивания, доставка, очистка/кэш, админ-функции, интеграционные и эксплуатационные тесты.
- `systemd` **отложен до самого конца**. Пока ручной запуск от `tgbot`; инструкция: `docs/debian-systemd.md` (несмотря на историческое имя файла).
- `config.yaml` изменён локально на сервере: перед `git pull` сохранять настройки и проверять конфликт.

## Критерий готовности

Не объявлять скачивание безопасным и не включать его для публичных пользователей до тестов реальных соединений, изоляции, лимитов, загрузки и отправки файлов, восстановления после ошибок и проверки работы от `tgbot`.
