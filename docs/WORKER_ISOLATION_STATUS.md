# Экспериментальная изоляция сетевого worker (не включена)

Модуль `bot/network_egress.py` строит команду для *привилегированного*
`systemd-run --system`. Это **не** рабочий механизм запуска worker из
Telegram-бота: пользователь `tgbot` не должен иметь права управлять системным
systemd или запускать сервисы от root.

## Ограничения подготовленной команды

- `User=tgbot`, `NoNewPrivileges=yes`, пустой `CapabilityBoundingSet`.
- `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`,
  `PrivateDevices=yes`, защита настроек ядра и cgroup.
- `MemoryMax=1G`, `TasksMax=32`, `RuntimeMaxSec=120`,
  `LimitFSIZE=2147483648`, `UMask=0077`.
- `IPAddressDeny` блокирует перечисленные локальные и зарезервированные
  сети, но **не является полным allowlist публичных IP**.

Эти параметры тестируются как построение команды, а не как реальная работа
cgroup/BPF. На конкретном VPS часть ограничений может не поддерживаться.
DNS может обращаться к локальному stub resolver и оказаться заблокированным.
**Нельзя** исправлять это снятием запрета на приватные сети или
жёстко заданным внешним DNS.

## Условия до включения загрузок

1. Отдельный установленный администратором системный worker или другой
   проверенный механизм IPC между непривилегированным ботом и worker.
2. Проверка фактического применения cgroup/BPF и лимитов ресурсов.
3. Успешный доступ к разрешённым публичным HTTPS-адресам и DNS через
   штатный резолвер системы.
4. Подтверждённая блокировка loopback, RFC1918, link-local, metadata-service,
   IPv6 ULA и других непубличных адресов **изнутри worker**.
5. Проверка перенаправлений, DNS rebinding, внутренних запросов yt-dlp,
   ограничений записи и завершения дерева процессов.

Пока эти условия не выполнены, пользовательские загрузки остаются
отключёнными. Диагностические пробы не считаются сертификатом безопасности.
