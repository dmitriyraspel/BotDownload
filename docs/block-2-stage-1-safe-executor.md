# Блок 2 / Этап 1 — безопасный исполнитель загрузок

Добавлен `bot.media_executor`: отдельный, явно включаемый API
`execute_media_download`, **по умолчанию отключённый**.
Он не подключён к worker IPC, диспетчеру, Telegram polling или очереди
отправки. Это не включает скачивание пользовательских задач.

## Защитные меры
- Принимаются только HTTPS URL строго определённых YouTube-хостов,
  без credentials, нестандартных портов, фрагментов и управляющих символов.
- Команда запускается через `create_subprocess_exec` без shell и без
  пользовательских аргументов командной строки, кроме URL после `--`.
- `yt-dlp` запускается без пользовательской конфигурации и плейлистов,
  без sidecar-файлов; вывод идёт в приватный каталог задачи.
- Ограничены время, CPU, адресное пространство, размер файла и
  число открытых дескрипторов. При отмене/тайм-ауте уничтожается
  группа процессов, включая дочерние процессы ffmpeg.
- Проверяется ровно один итоговый обычный файл, без hardlink,
  ненулевого размера и в заданном лимите. При ошибке каталог удаляется.
- До старта проверяются доступность хранилища и свободное место.

## Важные ограничения
**Это не production sandbox.** yt-dlp может обращаться к вторичным URL,
перенаправлениям и CDN. Проверка исходного URL сама по себе не защищает
от SSRF/DNS rebinding и не ограничивает сетевой egress. До подключения
к реальным задачам в следующем этапе нужны изоляция сети/egress,
ограничение разрешённых направлений и проверка цепочки запросов.
`RLIMIT_FSIZE` ограничивает размер отдельного файла, а не суммарную
запись и не заменяет квоту файловой системы. Нужны тесты сетевого
изолятора и суммарного дискового лимита.

## Проверка
```bash
.venv/bin/python -m pytest -q tests/test_media_executor.py
.venv/bin/python -m pytest -q
.venv/bin/python -m bot.main
```

Тесты этапа 1 не используют сеть и не загружают медиа.
Включать `enabled=True` на сервере с доступом к приватным сетям
пока нельзя. Отправка offline-фикстур пользователям запрещена.
